# VENITO — متجر الحلويات والمعجنات

منصة طلبات عربية باتجاه RTL، مبنية باستخدام Python 3.11+ وSQLite وواجهة JavaScript/CSS. قاعدة البيانات هي مصدر الأسعار والمناطق والطلبات؛ لا توجد منتجات تجريبية أو أسعار افتراضية.

## ما يعمل الآن

- واجهة متجر عربية متجاوبة مع بحث وتصنيفات وسلة محفوظة في SQLite.
- إدارة أصناف وأسعار وخيارات وصور عبر روابط أو رفع PNG/JPEG، مع شعار المتجر؛ تُخزّن الملفات المرفوعة في SQLite.
- تحقق الخادم من التوفر والأسعار والرسوم وساعات بغداد قبل إنشاء الطلب؛ لا تدخل الرسوم المجهولة في الإجمالي أو معاملة الدفع حتى يحددها المدير.
- طلبات مرقمة وسجل حالات وبيانات عملاء، ولوحة إحصاءات وتقارير ومخططات ومُرشّحات للطلبات.
- إيصال PDF عربي يُنشأ تلقائياً مع الطلب ويُخزّن في قاعدة البيانات؛ رابط العميل عشوائي وسري، ورابط الإدارة يتطلب جلسة الإدارة.
- لوحة إدارة عربية مع جلسات آمنة وCSRF وأدوار مدير النظام/المدير/الموظف.
- ساعات عمل افتراضية 12:00 ظهراً إلى 02:00 فجراً، مع إعداد يومي وتحقق صحيح لعبور منتصف الليل.
- طباعة شبكية حقيقية عبر TCP إلى طابعة ESC/POS، وإرسال اختبار وإيصال وتذكرة مطبخ.
- تسجيل معاملات الدفع؛ النقد عند الاستلام فقط مفعّل افتراضياً.
- ترحيلات SQL مرقمة ونسخ احتياطي متسق لقاعدة SQLite.

## التشغيل المحلي

يتطلب Python 3.11 أو أحدث والحزم المحددة في `requirements.txt` لإيصالات PDF العربية والتحقق من الصور.

```sh
python3 -m pip install -r requirements.txt
export HOST=127.0.0.1
export PORT=8000
export VENITO_DATABASE="$PWD/data/venito.sqlite3"
export ADMIN_USERNAME=venito-admin
export ADMIN_PASSWORD='ضع-كلمة-مرور-قوية-وفريدة-هنا'
python3 server.py
```

افتح `http://127.0.0.1:8000` للمتجر و`http://127.0.0.1:8000/admin` للإدارة. ينشئ أول تشغيل الجداول والتصنيفات العامة وساعات العمل، وينشئ حساب المدير من متغيري `ADMIN_USERNAME` و`ADMIN_PASSWORD` إذا كان اسم المستخدم غير موجود. **لا توجد بيانات دخول افتراضية.** خزّن كلمة المرور خارج المستودع وفي مدير أسرار بيئة الاستضافة. تغيير كلمة المرور في متغير البيئة لا يحدّث حساباً موجوداً؛ أنشئ حساباً بديلاً من قسم المستخدمين قبل تدوير الحساب الأول.

إعدادات التشغيل موضحة في [.env.example](./.env.example)، لكن التطبيق لا يحمّل ملف `.env` تلقائياً؛ مرّر القيم إلى بيئة العملية أو مدير الخدمات.

## أول إعداد للمتجر

1. سجّل الدخول إلى لوحة الإدارة.
2. أضف المنتجات وأسعارها الفعلية وصورها وروابطها وأي أحجام/خيارات. يمكن ترك السعر فارغاً مؤقتاً؛ المنتج غير قابل للشراء إلى أن يُدخل السعر.
3. راجع مناطق التوصيل ورسومها، وأدخل الرسوم الفعلية للمناطق المعروضة بعبارة «يحدد لاحقاً». يمكن قبول الطلبات لهذه المناطق مع بقاء الإجمالي النهائي معلقاً إلى أن تُحدد الرسوم.
4. أدخل الهاتف والعنوان وروابط التواصل وأوقات العمل الفعلية.
5. اختبر الطلب والدفع النقدي قبل نشر رابط المتجر.

## النشر

اربط الخدمة بعنوان HTTPS عبر وكيل عكسي مثل Caddy؛ يوجد مثال في [deployment/Caddyfile.example](./deployment/Caddyfile.example). يشغّل مثال systemd في [deployment/venito.service.example](./deployment/venito.service.example) التطبيق على `127.0.0.1`، ويُبقي قاعدة البيانات في `/var/lib/venito` خارج مجلد الشيفرة.

### Railway

يستخدم التطبيق `HOST` و`PORT` من بيئة التشغيل. اضبط `HOST=0.0.0.0`، واترك `PORT` لقيمة Railway، وحدد أمر التشغيل `python server.py`. أرفق Railway Volume وحدد `VENITO_DATABASE` إلى مسار داخل نقطة تركيب ذلك الـVolume، مثل `/data/venito.sqlite3`. قاعدة البيانات تشمل الإيصالات والصور والشعار؛ من دون تخزين دائم ستُفقد هذه البيانات عند إعادة إنشاء الحاوية. شغّل نسخة واحدة من التطبيق على ملف SQLite، واحتفظ بنسخ احتياطية خارج الـVolume.

- اضبط `COOKIE_SECURE=1` خلف HTTPS؛ وإلا لن تُرسل ملفات جلسة الإدارة على اتصال HTTP.
- أنشئ مجلد قاعدة البيانات وامنحه صلاحية الكتابة لمستخدم الخدمة فقط. لا تعرّض ملف SQLite أو منفذ التطبيق للعامة مباشرة.
- شغّل نسخة واحدة من التطبيق على قاعدة SQLite؛ لا تشارك ملف SQLite عبر خوادم متعددة.
- فعّل HTTPS، وحدّث نظام التشغيل، وراقب سجلات الخدمة والقرص، واختبر استعادة النسخ الاحتياطية دورياً.
- أنشئ نسخة متسقة بالأمر `python3 backup.py`، أو حدّد مساراً مثل `python3 backup.py /مسار-آمن/venito.sqlite3`. تُحفظ النسخ الافتراضية داخل `data/backups/` بصلاحيات مقيدة؛ انقل نسخة احتياطية مشفرة إلى تخزين منفصل وفق سياسة تشغيل المتجر.
- تحقق من عمل الموقع بعد النشر عبر `GET /api/health`.

## الطابعة الحرارية

التكامل الحالي يرسل أوامر ESC/POS الخام عبر TCP/IP، عادة إلى المنفذ 9100؛ يدعم إعداد عرض الورق 58 أو 80 مم ويختبر الاتصال من الخادم. من لوحة الإدارة أدخل عنوان IP والمنفذ، فعّل الطباعة، احفظ الإعدادات، ثم استخدم **إرسال ورقة اختبار**. من تفاصيل الطلب يمكن طباعة إيصال العميل أو تذكرة المطبخ.

يلزم توفير طابعة شبكة متوافقة مع ESC/POS، وتوصيل خادم التطبيق بها على الشبكة نفسها أو عبر مسار شبكي آمن. لا تفتح منفذ الطابعة للإنترنت. نجاح إرسال البيانات يعني أن اتصال TCP أُنجز؛ لا يستطيع الخادم تأكيد خروج الورق أو قصّه من دون استجابة خاصة بالطراز. تختلف الطابعات في دعم UTF-8 وتشكيل/اتجاه العربية؛ اختبر الجهاز الفعلي، وقد تحتاج طابعة/برنامجاً ثابتاً يدعم العربية صراحة. لا يوجد جهاز VENITO فعلي في بيئة التطوير، لذا لا يمكن اعتماد التوافق المادي قبل تزويدنا بطراز الطابعة واختبارها من شبكة الاستضافة.

## الدفع الإلكتروني

الدفع النقدي عند الاستلام هو الوسيلة الوحيدة الفعالة. توجد سجلات معاملات وحالات دفع، لكن **لا يوجد مزود دفع إلكتروني موصول أو تفعيل زائف لمدفوعات**؛ طلب الدفع الإلكتروني يُرفض حتى عند إرسال طلب مباشر إلى API. قبل إضافة مزود عراقي، يلزم تحديد حساب التاجر والمزود المتعاقد معه، وثائق API الرسمية وبيئة الاختبار، بيانات الاعتماد، وسياسة إشعارات الدفع/الاسترداد. لا تحفظ الأسرار في قاعدة بيانات عامة أو في الواجهة؛ أضفها عبر مدير أسرار بيئة الخادم بعد اختيار المزود والتحقق من عقده.

## الإشعارات والصور

تُسجّل إشعارات الطلب وتحديث الحالة داخلياً في قاعدة البيانات، لكن إرسال SMS/WhatsApp أو إشعارات خارجية لم يُفعّل لعدم اختيار مزود. تحتفظ روابط الصور الحالية بطريقة عملها؛ ويمكن رفع صور المنتجات وشعار المتجر بصيغتي PNG/JPEG، وتُحفظ الملفات المرفوعة ضمن قاعدة SQLite والنسخ الاحتياطية. لا توجد خدمة تخزين خارجية مطلوبة. يعتمد توليد PDF على ReportLab والخط العربي المضمّن مع المشروع، ولا يتصل بخدمة خارجية.

## الاختبارات

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile server.py database.py
node --check public/app.js
node --check public/admin.js
```

تغطي اختبارات التكامل ترحيل/اتصال قاعدة البيانات، حساب الطلب على الخادم، المناطق بلا رسوم، أوقات العمل بعد منتصف الليل، CSRF، إدارة الحالة، صفحات العميل، البحث والتصفية والتقارير، توليد وتنزيل الإيصال والتحقق من خصوصية رابطه، رفع الصور، وإرسال بيانات ESC/POS إلى مستقبل TCP اختباري. هذا يختبر بروتوكول الإرسال ولا يحل محل تجربة الطباعة على طراز الجهاز الفعلي أو اختبار المتصفح على هاتف حقيقي.
